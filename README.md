# EngKatakana
一个能将英文转换为中日韩音译词的软件
# 英単語 → 片仮名 / 한글 / 汉字（外来語学习）

把网页里的英文**即时转写成三种输出语言之一**，用来学外来词：

| 输出语言      | 效果                                            |
| --------- | --------------------------------------------- |
| **日语片假名** | `computer → コンピューター`（默认，原设计）                  |
| **韩语**    | `computer → 컴퓨터`；汉字按**一字一音**（한자음）：`计算机 → 계산기` |
| **中文**    | `bus → 巴士`（规则转写）或 `computer → 科恩皮塔`（强制音译）     |

纯本地运行，不联网、不上传任何页面内容。

---

## 安装（Chrome / Edge 手动加载）

1. 打开 `chrome://extensions/`
2. 右上角打开 **开发者模式**
3. 点 **加载已解压的扩展程序**，选这个 `EngKatakana` 文件夹
4. 装好后点工具栏图标，把开关拨开；快捷键 **Alt+K** 也能开关
5. 只对新打开的页面（或开关切换后）生效；已经开着的页面按 Alt+K 两下即可

> 注意：`chrome://`、扩展商店页、以及 Chrome 自带的 PDF 阅读器里无法注入，属正常限制。

## 两个正交的维度：输出语言 × 呈现方式

早期版本把「输出什么文字」和「要不要保留原文」揉在一个「显示方式」里，导致选中文外来词
就必须替换原文。v1.2.0 把它们拆成两个独立维度：

| 维度         | 取值              |
| ---------- | --------------- |
| **① 输出语言** | 日语片假名 / 韩语 / 中文 |
| **② 呈现方式** | 替换原文 / 保留原文+括号  |

所以「中文外来词」不再是第三档显示方式，而是 **输出语言=中文 + 子模式=规则转写**。

### 输出语言各有什么子选项

- **日语片假名**：无子选项，行为与旧版完全一致
- **韩语**：
  - **汉字走一字一音**（默认开）：`学 → 학`、`计算机 → 계산기`（韩语汉字的传统读音）
  - **汉字走普通话拼音**（默认关）：`xuexi → 쉐시`（按普通话读音搬到韩文）
  - 两个都开时拼音路线叠加在一字一音之上
- **中文**：
  - **规则转写**：查外来词表，`bus → 巴士`；表外词不造，保持原样
  - **强制转化**：把音强造成汉字，`computer → 科恩皮塔~`（带 `~` 标记）
    - 来源语言可分别开关：**英文**（默认开）/ **韩文**（默认开）/ **日文假名**（默认关）

> 韩语模式对**英文单词**是「查表优先、规则兜底」：常用词走精编表给标准写法
> （`computer → 컴퓨터`），表外词才按拼写规则拼一个念得出来的近似音。
> 这是因为英文拼写到韩文写法很多地方取决于**英语重音**，光看拼写推不出来
> （`coffee → 커피` 用 ㅓ，`robot → 로봇` 用 ㅗ，拼写型却一样）。

## 三段式行为：词典 → 虚词 → 规则推定

转换一个词时按这个顺序查：

| 顺序  | 来源                                                | 输出                   | 视觉标记               |
| --- | ------------------------------------------------- | -------------------- | ------------------ |
| 0   | **自定义词表**（你导入的）——优先级最高                            | `kubernetes → クバネテス` | **点线下划线**          |
| 1   | **主词典**（14,442 条）——日语里真在用的外来语，给标准写法               | `computer → コンピューター` | 实线下划线              |
| 2   | **虚词词典**（125 条）——`the / in / of / this`，**默认不启用** | `the → ザ`            | 实线下划线              |
| 3   | **规则推定**——词典里没有的新词，按英文拼写规则推                       | `webhook → ウェブフック`   | **虚线下划线 + 尾部 `*`** |

`*` 的含义是：**这个词是按拼写推出来的，日语里不一定这么写**，看到带星号的请当成「参考音」而不是「正确答案」。

### 为什么虚词要单独一个开关

日语里 `the / and / of / in / this` 这些**根本不作为外来语使用**。默认全部转换的话整页会变成
「ザ ネットワーク イズ ア …」，反而读不下去。所以默认关闭，需要时再打开。

唯一的例外是 **2 个字母的虚词**（`of / in / is / to / at / on / it / by / as …`）：
它们同时落在「短词闸门」里（2 字母的普通词默认不转，避免 `go / ok / id` 这种噪音）。
所以要让 2 字母虚词也转换，需要**同时打开**「虚词也转换」和「包含 2 字母短词」。

## 弹窗里的选项

**① 输出语言**（三选一）——见上方「两个正交的维度」

**② 呈现方式**（二选一）

- **替换原文**：英文直接换成目标文字，适合沉浸式阅读
- **保留原文 + 括号**：`computer（コンピューター）`，对照着记；推定词写作 `（レウールト*）`

**转换范围**

- **未命中词用规则猜测**（默认开）：词典里没有的词也转，带 `*`
  关掉它 = 只转「日语里确实存在的词」，整页更干净、零噪音
- **虚词也转换**（默认关）：`the / in / of / this` 这类
- **缩写后补（原文）**（默认开）：见下方「缩写补括号」

**其他**

- **悬停显示英文原词**：鼠标移上去显示 `computer → コンピューター`（零成本，用原生 `title`）
- **悬停显示汉语释义**：鼠标移上去显示中文意思。**首次打开会按需下载约 570 KB 释义表**
- **包含 2 字母短词**：`go / ok / id`（全大写缩写 `IT / AI` 始终会转）

**在此网站暂停**：按域名加入黑名单，之后这个站点不再注入。

**高级 / 极端选项**（折叠区，默认收起）

- **中文 / 韩文也转片假名**：仅日语输出下生效，见下方「极端模式」
- **未收录词按音译规则造 `~`**：仅中文输出的「规则转写」下生效
- **自定义词表**：见下方「导入自己的词表」
- **只转换我导入的词**：白名单模式，内置词典和规则猜测全部停用

## 什么会被跳过（重要）

### 网址、邮箱、域名、文件名一律不碰

早期版本会把 `https://github.com/...` 里的 `com` 也转成 `コム`，整条链接变成
`https://github.コム/...`，链接直接失效。现在扫描器是**一条带优先级的总正则**，
前面几组命中后整体保留、不进入转换：

| 保护区       | 例子                                               | 结果  |
| --------- | ------------------------------------------------ | --- |
| 协议 URL    | `https://github.com/Arnie97/Katakana-Terminator` | 原样  |
| `www.` 开头 | `www.example.co.jp`                              | 原样  |
| 邮箱        | `someone@example.com`                            | 原样  |
| 域名 / 带路径  | `raw.githubusercontent.com/a/b/c.json`           | 原样  |

TLD 只认**小写** `[a-z]{2,6}`，所以 `end.The` 这种句尾不会被误吞成域名；
`3.14` 也不会（没有 2–6 个字母的 TLD）。邮箱 / 域名之间不会互相截断，
整条 URL 作为一个「保留」token 通过。

### 标识符不会被切成词

`Arnie97`、`x86`、`my_var` 里的字母段即使能查词也**不转** ——
只要词的紧邻左边或右边是数字 / 下划线，就判定为标识符的一部分并整段跳过。
（`Katakana-Terminator` 里的连字符不算标识符连接符，两端各是一个正常单词。）

### 评论区 / Shadow DOM

B 站等站点已把评论区迁到 **Web Components + Shadow DOM**。普通 `TreeWalker` 穿不过影子边界，
所以遍历换成了**显式栈的迭代 DFS**，遇到 `shadowRoot` 就压栈继续走；
对于「先插进 DOM、过一会儿才挂 shadowRoot」的自定义元素（B 站就是这个模式），
还有一次 300 ms 的重试。

## 缩写补括号

`MCE`、`npm`、`IT` 这类缩写按字母名读时，输出是 `エムシーイー`、`エヌピーエム`、`アイティー`，
**看不出原来是什么缩写**。打开「缩写后补（原文）」后写成：

```
エムシーイー（MCE）
```

判定规则：

- 2–5 个**全大写**字母 → 缩写（`MCE` / `API` / `NASA`）
- 2–6 个**全小写、无元音、无 `y`** → 缩写（`npm` / `html` / `ssh`）
  - 排除 `y` 是为了让 `fly` / `my` / `rhythm` 仍按普通单词处理

括号是通过子元素 `<e2k-anno>` 渲染的，因为 `::after` 已经被 `*` 号和括号标注占用；
而且 CSS 的 `content` 不支持 `attr(attr(...))` 嵌套，所以括号必须落在真实元素上。

## 中文输出：规则转写

**输出语言 = 中文**，子模式 = **规则转写**时，命中音译词表就输出**通用中文写法**：

```
coffee → 咖啡      sofa → 沙发      logic → 逻辑
bus → 巴士         tank → 坦克      guitar → 吉他
```

词表是 **136 条**手工筛过的**真·音译词**（不是意译词冒充，比如 `computer → 计算机`
是意译，不进表）。表里没有的词：

- 默认**保持原样**（不硬造）
- 打开「未收录词按音译规则造 `~`」后，按片假名 → 常用音译汉字的映射**硬造一个**，
  带 **`~` 号 + 虚点下划线**，例如 `webhook → ウェブフック → ウェブフック~ → 韦布胡克~`

> `~` 的含义和 `*` 一样，是「这是规则造的，中文里没有这个写法」。
> 打开这个选项时必须接受**会出现生造词**，它只是帮你记住读音轮廓。

---

## 中文输出：强制转化

子模式 = **强制转化**时，无视词表，把来源语言的音**一律强造成汉字**，带 `~` 标记：

```
computer → 科恩皮塔~         （英文来源）
컴퓨터 → 空浦特~             （韩文来源）
```

来源语言可分别开关（在「强制转化」下方出现的勾选项）：

| 来源       | 默认    | 说明                  |
| -------- | ----- | ------------------- |
| **英文**   | **开** | `computer → 科恩皮塔~`  |
| **韩文**   | **开** | 按谚文音节读音强造汉字         |
| **日文假名** | **关** | 假名本来就已是表音文字，通常不需要再转 |

> 日文假名默认关，是因为片假名**本身就是音**（`コンピューター` 一眼就能读），
> 再强行套一层汉字音译反而更难认。需要时再打开。

## 极端模式：中文 / 韩文转片假名（日语输出下的附加项）

**输出语言 = 日语片假名**时，打开「中文 / 韩文也转片假名」，汉字按**普通话拼音**、
谚文按**韩语读音**转写成片假名：

```
计算机 → ジースアンジー        香港 → シアンガン
한국어 → ハングゴ               안녕하세요 → アンニョンハセヨ
```

**中文**走的是「中国語カナ表記」通行方案：`zh→ジ / q→チ / x→シ / r→ル`，
韵母 `en→エン / eng→オン / e→オー`，`jqx + u` 视作 `ü`（`jue → ジュエ`），
`zhi/chi/shi/ri/zi/ci/si` 按整体音节处理。拼音表由 `pypinyin` 生成，
覆盖 `U+4E00..U+9FA5` 的 **20,902 字（99.9%）**，多音字取最常用读音。

**韩文**不需要词表：谚文是音节文字，Unicode 里就是「初声 19 × 中声 21 × 终声 28」的笛卡尔积，
直接分解拼装即可。额外做了三条最常见的音韵规则：

| 规则                  | 例子                          |
| ------------------- | --------------------------- |
| 有声音化（响音后的平音浊化）      | `아가 → アガ`                   |
| 鼻音化（收音 ㅂ/ㄱ/ㄷ + ㄴ/ㅁ） | `합니다 → ハムニダ`                |
| 连音（收音挪到下一音节的 ㅇ 位）   | `일본어 → イルボノ` / `한국어 → ハングゴ` |

> **诚实的说明**：它是**按读音转写**，**不是翻译**，输出**不是日语词汇**。
> 打开后整页中文/韩文会变成一串片假名，可读性大幅下降 —— 它只适合「拿来看某几个字怎么读」，
> 日常阅读请不要开着。这是设计上的取舍，不是 bug。
>
> 注意：这个开关**只作用于日语输出**。韩语输出下汉字走一字一音，中文输出下汉字本来就不动。

## 韩语输出：汉字一字一音

**输出语言 = 韩语**时，网页上的汉字按**韩语汉字音（한자음）**逐字转成谚文：

```
国家 → 국가        计算机 → 계산기      香港 → 향항
学 → 학            习 → 습             体 → 체
```

数据来自 Unihan 的 `kKorean` 字段，共收录 **10,520 个**有韩国读音的汉字。

> **为什么只有一半的汉字有读音**：韩语实际只使用约 1 万个汉字，`U+4E00..U+9FA5`
> 里的 20,891 个字中只有 **50.3%** 有通行读音。剩下的一半**本来就该是空**——
> 硬造读音比留空更糟，所以遇到没有读音的字会**保留原字**，不瞎猜。
>
> **繁体优先**：Unihan 只收繁体字头。简体字若是「借用古字形」来的，会带上古音，
> 所以查表时优先取该字的繁体异体读音。例：`机` 从「機」读 **기**（不是古字「机」的 궤），
> `体` 从「體」读 **체**（不是 분）。

**英文单词**在同一模式下走「查表优先、规则兜底」：常用词查精编表给标准写法，
表外词才按拼写规则拼近似音。规则拼出来的词**不加标记**——因为韩语外来语的罗马字
转写本身就没有唯一标准，标出来反而误导。

## 导入自己的词表

「高级 / 极端选项」里有一块自定义词表。**一行一条**，四种格式都认：

```
kubernetes=クバネテス        # word=片假名（推荐）
vite	ヴィート               # Tab 分隔
react,リアクト                # 逗号分隔
nuxt ナクスト                 # 空格分隔
```

也接受 JSON：`{"kubernetes":"クバネテス","vite":"ヴィート"}`

- **导入文件**（`.txt` / `.tsv` / `.csv` / `.json`）只把内容**填进文本框**，
  **必须再点「保存」才生效** —— 避免导入即覆盖
- **保存**：写入 `chrome.storage.local`（不占同步配额，也不会上传）
- **清空**：删除整份自定义词表
- 自定义词**优先级高于内置词典**，可以覆盖内置结果，视觉上是**点线下划线**
- 打开 **只转换我导入的词** = 白名单模式：只转你表里的词，内置词典 / 推定 / 虚词全部停用。
  适合「我这一轮只想背这 50 个词」

## 悬停：看清原词和意思

- **悬停显示英文原词**（默认开）：`computer → コンピューター`。
  用原生 `title` 属性实现，**零成本、零 DOM 插入**
- **悬停显示汉语释义**（默认关）：一整页都是片假名时，鼠标移上去能看到
  `computer / コンピューター / 计算机；电脑` 三行，以及它是**词典命中**、**推定**、
  **自定义**还是**外来词**标签。这一项需要下载约 570 KB 的释义表（14,586 条），
  **只在打开时才拉取**

只要「悬停显示汉语释义」开着，就用一个自绘的 `<e2k-tip>` 气泡
（`position:fixed`、`pointer-events:none`、`z-index` 拉满、关键样式 `!important`），
以便在页面 CSS 很凶的站点上也能正常显示；同时用 `closest()` **和**
`event.composedPath()` 两种方式定位悬停元素，所以影子里（评论区）的词也能出提示。
关掉它则回退到原生 `title`。

```
└── data/
    ├── engine.js          规则推定引擎（词典未命中时使用）

    ├── ko.js              英文 → 韩文（查表 + 规则）、假名 → 韩文、拼音 → 韩文
    ├── ko-table.js        英文 → 韩文精编外来语表 169 条
    ├── hanja.js           汉字 → 韩文读音表解析（一字一音）

    ├── pinyin.txt         拼音表 409 音节 / 20,902 字（按需加载）
    ├── hanja.txt          汉字音表 489 读音 / 10,520 字（按需加载）

```

**按需加载**是刻意的：`zh.json`（570 KB）只在开「悬停显示汉语释义」时拉，
`loan-zh.json` 只在中文输出的「规则转写」下才拉，`pinyin.txt` 只在
日语输出 + 开「中文 / 韩文也转」时拉，`hanja.txt` 只在韩语输出时拉。
不开这些功能的用户一个字节都不下载。

### 为什么用自定义标签而不是直接改文本

每个被改动的文本节点都被一个 `<e2k-box>` 容器包住，容器里是若干 `<e2k-w>`。
关掉开关时把容器**换回原来那个 Text 节点**，再 `normalize()`，
所以能保证逐字节还原、不留残留元素。`e2k-box` 被 CSS 强制回退成 `display:inline`，
不影响原页面排版。

| 来源                                                                                                    | 说明                                             |
| ----------------------------------------------------------------------------------------------------- | ---------------------------------------------- |
| [KEINOS/google-ime-user-dictionary-ja-en](https://github.com/KEINOS/google-ime-user-dictionary-ja-en) | Google 日语 IME 用户词典的英日对照，主力来源                   |
| [JMdict](https://www.edrdg.org/jmdict/j_jmdict.html)（jmdict-simplified，commonOnly）                    | 第二来源，补上日语文化词（アニメ / カタカナ / マンガ …）               |
| [KyleBing/english-vocabulary](https://github.com/KyleBing/english-vocabulary)                         | 英汉释义（初中/高中/四级/六级/考研/托福/SAT 合并）                 |
| [pypinyin](https://github.com/mozillazg/python-pinyin)                                                | 汉字拼音表（生成 `pinyin.txt`）                         |
| 人工校准                                                                                                  | 898 条，覆盖高频词、日语文化词、术语、以及上游的错条目；另 136 条音译词单独手工整理 |

构建时逐层过滤，保证进词典的都是「日语里真的这么写」的词：

1. **结构闸**：片假名那一列必须是纯片假名（`back → コシ`（腰）这种被挡掉）
2. **音形闸**：英文与片假名的辅音骨架（清浊归一、l/r 合并）相似度 ≥ 0.5
   （`police → ポリ`、`place → カショ` 这种被挡掉）
3. **缩写闸**：全大写缩写降权，避免 `MAN` 顶掉小写 `man`
4. **黑名单 / DROP**：`sell → セル`（=cell）、`read → リード`（=lead）、
   `lose → ルーズ`（=loose）这类「片假名是另一个词」的，宁可没有也不给错

### 已知局限

- 上游是**技术向** IME 词典，日常/文化词覆盖不全，靠 JMdict + 人工校准补
- 词典是「这个词在日语里存在吗」，**不保证语义对应**。例如 `let` 命中 `レット`
  （网球术语），出现在 `Let me explain` 里就属于噪音 —— 这也是「关掉推定、
  甚至整个关掉」值得用的原因
- 规则推定是**拼写 → 发音的近似**，不是音标。短音 `u`、`-er`、`all/alk`、
  `type/byte`、软硬 `g` 等常见规则都做了，但英语拼写本身就不可靠
  （`through / tough / though` 无法从拼写区分），带 `*` 的都是参考音
- 音译词表只有 136 条，是**白名单**不是全覆盖；`~` 造出来的写法**中文里不存在**
- 汉字转写是**普通话读音**，同一汉字多音字只取最常用读音，专有名词、古音、方言都会不准

### 规则推定已处理的读音规则（部分）

| 规则                  | 例子                                                |
| ------------------- | ------------------------------------------------- |
| 闭音节短 `u` → ア        | `bus→バス` / `jump→ジャンプ` / `club→クラブ`               |
| `ur` + 辅音 → アー      | `turn→ターン` / `hurt→ハート` / `surf→サーフ`              |
| 词尾 `-er` → アー       | `render→レンダー` / `trigger→トリガー` / `user→ユーザー`      |
| `all` / `alk` → オー  | `install→インストール` / `talk→トーク` / `callback→コールバック` |
| `y` + 辅音 + `e` → アイ | `type→タイプ` / `typescript→タイプスクリプト`                |
| `wor` → ワー          | `work→ワーク` / `world→ワールド`                         |
| 软 / 硬 `g` 区分        | `engine→エンジン` vs `git→ギット`、`trigger→トリガー`         |
| 促音只来自拼写重复辅音         | `back→バック` / `happy→ハッピー`，但 `snippet→スニペット`       |
| 词尾单独 `p/t/k` 出促音    | `cap→キャップ` / `submit→サブミット`                       |
| 无元音缩写按字母名读          | `npm→エヌピーエム` / `html→エイチティーエムエル`                  |
| 虚词闸门（推定时也屏蔽）        | `the / and / of` 永不被「推」成 ザ / アンド / オブ             |
